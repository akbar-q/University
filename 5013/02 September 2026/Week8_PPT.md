# Week 8 - Individual Competence, Video Evidence and Wider Impact (3-4h)

---

## Slide 1: Consolidation Week

- Demonstrate that each student can program, test, explain and evaluate an embedded system.
- Prepare the LO3 video recording and the supervised programming test.
- Begin structured research for the LO4 stakeholder presentation.

---

## Slide 2: Learning Objectives

- Plan a solution from a blank Arduino sketch.
- Debug a small program methodically.
- Record a concise, evidence-based individual technical video.
- Distinguish current uses, trends and broader impacts of embedded systems.
- Build an LO4 research plan with credible sources.

---

## Slide 3: The Programming-Test Pattern

From a blank sketch, students need to show:

- pin/bus/sensor initialisation;
- at least one input read;
- processing: threshold, scaling, filtering or range check;
- output: LED, buzzer, relay, PWM or serial response;
- error/fault handling;
- visible test/debug evidence.

---

## Slide 4: Lab L15 - Timed Programming Rehearsal (90 min)

**Scenario:** create a light-responsive controller.

- Read an LDR every 250 ms.
- Use a button to select `AUTO`, `MAX` or `OFF` mode.
- In `AUTO`, control LED output from the sensor reading.
- Print the mode and reading every second.
- Include one range/fault check.

**Rules:** work independently; use local documentation only; retain final code and test record.

---

## Slide 5: Debugging Under Time Pressure

1. Re-read the requirement and make a pin map.
2. Prove each input/output with a minimal sketch.
3. Build the decision logic.
4. Add serial diagnostics.
5. Test normal, edge and fault conditions.
6. Improve only after a working baseline is saved.

---

## Slide 6: Lab L16 - Peer Review and Video Practice (45 min)

- Each student demonstrates their alarm/simulation to a peer.
- Peer asks: what does this code section do, how was it tested, what failed, what changed?
- Student records a 2-minute trial explanation.
- Peer provides one evidence-based improvement suggestion.

---

## Slide 7: LO3 Video Recording Structure

| Time | Content |
| ---: | --- |
| 0:00-0:45 | Purpose, requirements and system block diagram |
| 0:45-2:30 | Code walkthrough: input, decision and output |
| 2:30-3:45 | Test plan and evidence |
| 3:45-5:00 | Bug, diagnosis and fix |
| 5:00-7:00 | Evaluation, peer feedback and improvement |

---

## Slide 8: LO4 - Embedded Systems in the Wider Environment

- Current uses: smart buildings, manufacturing, healthcare, transport and agriculture.
- Trends: IoT, edge AI, cybersecurity, low-power design and digital twins.
- Industrial robotics: sensing, control, collaborative robots and safety systems.
- Wider impact: cost, maintenance, skills, privacy, accessibility and sustainability.

---

## Slide 9: Build an Evidence-Based Presentation

- Select one sector related to environmental monitoring or industrial automation.
- Find 3-5 current embedded-system applications.
- Use cited visuals: one adoption/trend chart and one system architecture diagram.
- Compare benefits, limitations, risks and mitigations.
- Make claims traceable to credible sources.

---

## Slide 10: Final Evidence Checklist

- Simulator/hardware project and commented code.
- Initial and refined test plan/results.
- Screenshots, serial logs and issues-and-fixes record.
- Individual LO3 video recording.
- Programming-test evidence pack.
- LO4 research plan and presentation outline.

---

## Slide 11: Beyond This Unit

- Move from simulator to hardware with the same test discipline.
- Compare Arduino, ESP32 and STM32 using application requirements rather than popularity.
- Extend the alarm with real environmental sensors, data logging or safe connectivity only after the core design is reliable.

---

## Slide 12: Final Reflection

- Which input, output and code pattern can you now explain confidently?
- Which test result best proves your system works?
- Which limitation would you improve first, and why?
